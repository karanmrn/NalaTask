# Assumptions, unresolved contracts and production gates

All schema facts and requirements come from `assessment_brief.md`. The following are implementation decisions, not undocumented claims about NALA.

| Topic | Implemented decision | Production confirmation or improvement |
|---|---|---|
| Raw layout | Configurable `RAW.PAYMENTS`, `RAW.FINCRIME`, `RAW.AMPLITUDE` schemas; unquoted Snowflake identifiers. | Confirm actual table mapping and case. |
| CDC shape | One current row per declared primary key; replica applies updates and hard deletes. Uniqueness violations fail rather than choosing an arbitrary winner. | Confirm current-state vs append-only format, commit ordering, replay, schema changes and deletion markers. Do not use this stage directly on an append-only CDC log. |
| Cross-source consistency | Production builds must use a stable, approved raw snapshot/checkpoint. | A Snowflake snapshot cannot repair differing source replication lag. Align connector watermarks or retry transient relationship failures after an agreed grace period; do not silently warn on permanent orphans. |
| Freshness | No supplied column is treated as connector ingestion time. Source freshness is deliberately unset. | Gate on actual StreamServe lag/checkpoints and Fivetran completed sync. Configure row freshness only when an actual metadata column exists. Never use current_timestamp as loaded_at. |
| Time zones | Source timestamps represent UTC, cast to TIMESTAMP_NTZ. | Confirm application and connector timestamp interpretation. |
| Finance day | Creation-day cohort, evaluated using current transaction state. | Finance must approve; completion-date accounting requires a true completed_at or authoritative event history. Latest updated_at is not used as a hidden completion date. |
| Outbound types | Three disbursement types plus outgoing P2P and conversion-outgoing-P2P. Incoming, collection-only, conversion-only, reward and reversal types are excluded. | Validate whether NALA excludes internal P2P from commercial volume. Change the central seed, not individual dashboards. Do not require recipient_id for non-disbursement types. |
| USD conversion | New approved `daily_fx_rates` input; 1 sent-currency unit = usd_per_unit USD, effective creation date. USD identity = 1. | Source not supplied. Missing/invalid rates fail publication; do not substitute sent-to-received exchange_rate or invent rates. No forward-fill without Finance approval. |
| Local volume | Aggregate with sending currency/corridor. | Enforce currency grouping in approved Hex/saved-query interfaces. MetricFlow alone can still produce a meaningless mixed-currency sum; this is an explicit serving constraint. |
| Duration | Attempt last_updated_at and task last_updated_at used only as visibly named proxies for currently terminal records. | Add exact completed_at/failed_at/resolved_at or state-event history. Do not label these proxies as measured terminal-event times. |
| Attempt denominator | All attempt states, including waiting/ambiguous/reversed. | This is the brief's definition. Show pending age and maturity separately rather than changing it. |
| Formal review FPR | FALSE_POSITIVE / all formal reviews, including INCONCLUSIVE and repeated review records. Review-day axis. | Match the explicit brief. It is not statistical FP/(FP+TN), and inline review status does not supply the denominator. |
| Rule identity | Join execution.rule_id to exact rule-version ID, preserving deleted definitions. | Validate whether immutable versions can be edited. Do not join by name and choose the latest. |
| Trigger rate | FAIL / all executions is a provisional trigger proxy. | Confirm engine semantics before calling FAIL an alert or interpreting noise. ERROR is separate. |
| Task mapping | Typed entity + relevant action + preceding 60-minute window. Only a single candidate gets an inferred link. Others remain counted. | Request task.workflow_execution_id. Even a unique candidate is not a proven causal relationship. Time-window sensitivity and clock skew need analysis. |
| Task array positions | `user_review`: [0] user. `transaction_review`: [0] transaction, [2] user. Explicit disbursement context may identify a transaction. | The brief says 'typically'; validate contracts per task type. Unsupported/contradictory context remains explicit, not guessed from UUID format. |
| Anonymous events | Infer a user only when exactly one user is observed for that device in the window. Explicit user IDs take precedence. | A unique observed device mapping is still a POC heuristic, not verified identity; shared-device events remain unresolved. |
| KYC completion | Require `kyc_step.completed` with explicit `event_properties.is_final_step=true`. | The key is an assumed proposed instrumentation contract, not supplied fact. Without it, the strict KYC stage is unknown and a warning is raised; the independent signup-to-transaction duration still works. |
| Funnel window | 90 days by event_time before run start; first means first observed within that interval. | Not lifetime first; late loads, client clocks and left/right censoring apply. Production needs identity and event-completeness contracts. |
| Country | Required duration metric uses IP country at selected signup-completed event. | Not residence. Stage-conversion rates by this country are selection-biased: abandoned starts have unknown signup country. Use overall funnel or add a stable start-country analysis before country comparisons. |
| Full rebuild baseline | Persisted narrow production tables for correct propagation of mutable joins; no guessed high-volume watermarks. | Not certified to meet hourly cost/latency goals. Benchmark; introduce connector changed-key feeds and bounded restatement, then reconcile against full rebuild. |
| Incremental option | Attempt-only opt-in filters by last update with three-day overlap and MERGE on full key. | Validate timestamp advancement, latency and no hard deletes in this mode; periodic reconciliation alone does not make missed changes correct between runs. Keep disabled until these gates pass. |

## Release gates

A production release requires actual source access, confirmed replica and freshness contracts, approved financial/time definitions, real FX coverage, native dbt/MetricFlow validation, representative Snowflake execution and cost testing, a safe publish/rollback process, and a reviewed access model. The project includes code and proposals for these boundaries; it does not claim live production approval.
